## 一、核心技术机理与故障定位

在 节点连上但打不开网页排查全流程 Checklist 场景下，用户经常遭遇的核心瓶颈是：排查 DNS 污染、系统代理环境变量篡改与端口冲突。

从 TCP/IP 与 TLS 协议栈底层剖析，该故障通常与以下微观机制强相关：
1. **TCP 三次握手与 TLS Client Hello 阻断**：客户端向节点发送 SYN 包正常收到 SYN+ACK，但随后在发送包含 SNI 域名的 Client Hello 时，数据包被路由中间盒（Middlebox）静默丢弃（RST 阻断），导致客户端长时间报 `Handshake timeout`；
2. **系统代理注册表篡改与环境变量劫持**：部分 Windows 第三方安全卫士或清理工具会在后台强行重置注册表代理键值，导致 Clash 的监听端口与系统实际发包端口不一致；
3. **DNS 递归死锁与 Fake-IP 缓存冲突**：本地网络解析 Fake-IP 模式下生成的 198.18.0.x 虚拟地址时，由于客户端非正常退出，本地网络 DNS 保持为 127.0.0.1，导致所有网站出现 DNS 解析失败。

## 二、标准排障命令行诊断工具链

遇到疑难故障时，请在命令行中按序执行以下三条精准诊断命令：

```bash
# 1. 检验与节点服务器的基础 TCP 连通性 (测试 443 端口是否可达)
Test-NetConnection -ComputerName 节点服务器域名 -Port 443

# 2. 测量通过本地代理的 TLS 握手耗时与 HTTP 状态码
curl -x http://127.0.0.1:7890 -I -s -w 'TLS握手耗时: %{time_appconnect}s, 总耗时: %{time_total}s
' https://www.google.com/generate_204

# 3. 彻底清空本地 DNS 解析死锁与缓存
ipconfig /flushdns
```

## 六、常见问题权威解答 (FAQ)

### Q1: 遇到无法排查的疑难杂症，最快恢复网络的方式是什么？
在客户端中彻底清空已有订阅配置，重新从机场官网用户中心拉取最新订阅链接，并重启客户端与本地操作系统。

### Q2: 为什么手机端不需要设置代理端口？
移动端客户端（如 iOS Shadowrocket、Android Clash Meta）原生通过创建系统级的 VPN 虚拟网卡（Network Extension）接管全局流量，因此无需像桌面端那样配置环境变量端口。

### Q3: 为什么有时候节点延迟很低，但测速速度却很慢？
客户端显示的 Ping 延迟仅代表本地到国内入口服务器的往返时间，并不代表出口可用带宽。若节点出口服务器被大量用户跑满，就会出现低延迟但低吞吐的拥塞现象。
